## Core Message

- This is the current formal public release of the ACL-X hybrid strategy.
- Release messaging is quality-first: validated output quality must stay flat or improve.
- The main optimization target in the current version is elapsed time.
- Token behavior is real but tier-dependent rather than universal.
- Follow-up work will continue to strengthen both time optimization and token optimization on top of the current release.
- User feedback, failure cases, and benchmark comparisons are welcome.

## Advantages

- Adaptive `t0/t1/t2/t3` routing keeps simple tasks light and promotes only when runtime structure really needs it.
- Quality-first release discipline avoids selling token savings at the cost of output quality.
- Time optimization is already strong in the validated heavy suites.
- The repository ships benchmark evidence, bilingual docs, and a Codex-oriented share pack instead of only abstract design notes.

## Intended Audience

- Teams or individual builders running bounded local AI-agent workflows.
- Users who need clearer handoff structure, reusable runtime state, or checkpointed multi-step work.
- Codex users who want a packaged default-on installation path today.
- Other agent-host builders who are willing to integrate the protocol, prompt, and runtime pieces manually.

## GitHub Release Blurb

ACL-X v0.3.2 is the current formal public release of the hybrid strategy.

This release packages the validated adaptive routing behavior, bilingual documentation, fresh heavy benchmark evidence, and the Codex-oriented share-pack installation path into a publishable public repository.

In one line: ACL-X helps bounded local agent workflows stay quality-first, optimize time aggressively where validated, and add machine-readable structure only when the runtime facts justify it.

The release message is intentionally strict: ACL-X hybrid is quality-first, with elapsed time as the main optimization target. Token gains are real but tier-dependent, not universal. The current evidence is strongest on `t1`, while `t2` and `t3` should still be described as time-first tiers with possible but non-guaranteed token upside.

We will continue improving this version after launch, with ongoing work focused on stronger time optimization and stronger token optimization without lowering output quality. Usage reports, benchmark comparisons, and failure cases are welcome.

## Long Announcement

We are publishing the current formal public release of the ACL-X hybrid strategy as `v0.3.2`.

This release turns the current hybrid routing and runtime behavior into a public repository with source-install support, heavy benchmark artifacts, bilingual release documentation, and a Codex-oriented share-pack for default-on installation on supported hosts.

Who this is for: builders and operators of bounded local AI-agent workflows who want clearer routing, cleaner handoffs, reusable machine state, and faster validated execution without giving up output quality discipline.

The public message stays disciplined:

- quality comes first
- elapsed time is the primary optimization target
- token improvement is real but depends on tier and task shape
- Codex gets the packaged default-on installation path in this release
- other agent hosts can reuse the strategy manually, but do not yet get a packaged default installer here

This is not a claim that every task will improve on every metric. The current release remains bounded by the validated task families documented in the repository.

After launch, we will continue strengthening the current version with more time optimization and more token optimization, while holding the line on output quality. We welcome real-world usage feedback, issue reports, benchmark reruns, and examples of tasks that still regress or route poorly.
