# ACL-X 正式更新文案包

英文版见 [launch_announcement.md](launch_announcement.md)。

本文汇总当前 ACL-X hybrid 策略公开更新版本可直接复用的对外文案。

## 核心口径

- ACL-X `v0.3.3` 是当前 hybrid 策略的正式公开更新版本。
- 对外发布口径继续坚持质量优先：已验证测试集上的输出质量必须持平或更好。
- 当前版本的主要优化目标仍然是耗时。
- token 收益真实存在，但它依赖 tier，不是普遍保证。
- 本次更新最重要的变化，是用新的通用任务重型运行强化了公开 `t2` 效率口径。
- 欢迎大家继续提供使用反馈、失败样例和 benchmark 对比结果。

## v0.3.3 更新内容

- 将公开通用任务 benchmark 包刷新到合并运行 `20260415_110636_t2_refresh`。
- 用修复后的结果替换此前偏弱的公开 `t2` 切片，提升了 `t2` 的公开效率表述基础。
- 将公开源码树、锁定策略文件、runtime/session 关键面以及行为锁定测试同步到当前接受状态。
- 保持双语公开报告、机器可读 benchmark 工件和面向 Codex 的安装资产一致。

## 头部基准结论

- 通用任务重型 `20260415_110636_t2_refresh`：聚合 token 优化 `31.78%`，聚合时间优化 `54.12%`，质量差值 `+0.75`。
- 预发布重型 `20260413_152717`：聚合 token 优化 `66.35%`，聚合时间优化 `71.16%`，质量差值 `+5.00`。
- 当前对外 tier 口径是：`t1` 仍然是最清晰、最低风险的 token 与时间双重优化层；`t2` 现在可以支撑更强的公开效率表述；`t3` 仍应表述为时间优先、token 收益较小；`t0` 仍应表述为精确性优先。

## 面向对象

- 运行有边界本地 AI agent 工作流的团队或个人开发者。
- 需要更清晰 handoff 结构、可复用运行时状态或 checkpoint 多步任务的人。
- 想直接使用打包默认启用安装路径的 Codex 用户。
- 愿意手动接入协议、prompt 与 runtime 组件的其他 agent 宿主开发者。

## GitHub Release 简版文案

ACL-X `v0.3.3` 是当前 hybrid 策略的正式公开更新版本。

这次更新刷新了公开 benchmark 包，把发布源码树同步到当前锁定策略状态，并且在不降低已验证输出质量的前提下，强化了 `t2` 的公开效率叙事。

如果要用一句话概括：ACL-X 适合有边界的本地 agent 工作流，在保证质量口径不放松的前提下，优先争取更好的耗时表现，并且只在运行时事实确实需要时才引入 machine-readable 结构。

这次发布口径仍然刻意收紧：ACL-X hybrid 是质量优先策略，当前主要优化目标是耗时。token 收益确实存在，但它依赖具体 tier，不是普遍性的统一收益。更新后的公开证据现在支持更强的 `t2` 表述，而 `t3` 仍应被描述为时间优先、token 收益较小，`t0` 仍应被描述为精确性优先。

在 `v0.3.3` 之后，我们会继续围绕当前发布线加强时间优化与 token 优化，同时确保输出质量不下降。欢迎大家提交真实使用反馈、benchmark 对比和失败案例。

## 长版更新公告

我们将 `v0.3.3` 作为当前 ACL-X hybrid 策略的正式公开更新版本对外发布。

这次更新保持仓库与当前锁定策略状态一致：刷新后的重型 benchmark 工件、同步后的源码与测试面、双语发布文档，以及面向 Codex 的 share-pack 默认安装链路，都已经对齐到同一条发布线。

它主要面向这类用户：希望在有边界的本地 AI agent 工作流里获得更清晰的路由、更稳定的 handoff、更可复用的 machine state，以及更好的验证内耗时表现，同时又不愿意牺牲输出质量。

这次对外发布继续坚持以下边界：

- 质量优先
- 耗时是当前最主要的优化目标
- token 优化真实存在，但依赖 tier 与任务形态
- 当前版本提供 Codex 的默认启用安装路径
- 其他 agent 宿主可以手动复用，但当前仓库还没有给它们提供打包好的默认安装器

`v0.3.3` 最重要的对外变化，是 benchmark 可信度和发布面一致性。新的通用任务运行把公开聚合结果刷新到 `31.78%` token 优化和 `54.12%` 时间优化，同时保持质量不退化；它也用修复后的结果替换了此前偏弱的 `t2` 公开切片，使 `t2` 的公开效率表述更加稳健。

这仍然不是一个“任何任务都会在所有指标上统一变好”的声明。当前版本依然受限于仓库中已经明确给出的验证任务范围。

在这次更新之后，我们会继续围绕当前版本加强时间优化和 token 优化，同时守住输出质量不下降这条底线。也欢迎大家把真实工作负载、回归样例、路由不稳定样例和 benchmark 复测结果反馈给我们。
