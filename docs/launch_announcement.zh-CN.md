# ACL-X 首发公告文案包

英文版见 [launch_announcement.md](launch_announcement.md)。

本文汇总当前 ACL-X hybrid 策略正式公开发布版本可直接复用的对外文案。

## 核心口径

- 这是当前 ACL-X hybrid 策略的正式公开发布版本。
- 对外发布口径坚持质量优先：已验证测试集上的输出质量必须持平或更好。
- 当前版本的主要优化目标是耗时。
- token 收益是真实存在的，但它严格依赖 tier，不是普遍保证。
- 后续会继续在当前版本基础上加强时间优化和 token 优化。
- 欢迎大家提供使用反馈、失败样例和 benchmark 对比结果。

## 项目优势

- 自适应 `t0/t1/t2/t3` 路由让简单任务保持轻量，只有在运行时结构确实需要时才升级。
- 质量优先的发布纪律，避免为了宣传 token 节省而牺牲输出质量。
- 在已验证的重型测试中，时间优化已经有比较明确的优势。
- 仓库交付的是 benchmark 证据、双语文档和面向 Codex 的 share pack，而不只是抽象设计说明。

## 面向对象

- 运行有边界本地 AI agent 工作流的团队或个人开发者。
- 需要更清晰 handoff 结构、可复用运行时状态或 checkpoint 多步任务的人。
- 今天就想用打包默认启用安装路径的 Codex 用户。
- 愿意手动接入协议、prompt 与 runtime 组件的其他 agent 宿主开发者。

## GitHub Release 简版文案

ACL-X v0.3.1 是当前 hybrid 策略的正式公开发布修复版。

这个版本把已验证的 adaptive routing 行为、双语文档、最新重型 benchmark 证据，以及面向 Codex 的 share-pack 默认安装路径，整理成了可以直接公开发布的仓库。

如果要用一句话概括：ACL-X 适合有边界的本地 agent 工作流，在保证质量口径不放松的前提下，优先争取更好的耗时表现，并且只在运行时事实需要时才引入 machine-readable 结构。

这次发布的口径是刻意收紧的：ACL-X hybrid 是质量优先策略，当前主要优化目标是耗时。token 收益确实存在，但它依赖具体 tier，不是普遍性的统一收益。当前最强证据仍然来自 `t1`，而 `t2` 与 `t3` 更适合表述为“时间优先，token 可能改善但不承诺”。

发布之后，我们会继续围绕当前版本加强时间优化与 token 优化，同时确保输出质量不下降。欢迎大家提交真实使用反馈、benchmark 对比和失败案例。

## 长版首发公告

我们正式公开发布了当前 ACL-X hybrid 策略的正式版本修复线。

这个版本把当前 hybrid 路由与运行时行为整理成了一个可公开复用的仓库，包含源码安装工作流、重型 benchmark 工件、双语发布文档，以及面向 Codex 的 share-pack 默认安装链路。

它主要面向这类用户：希望在有边界的本地 AI agent 工作流里获得更清晰的路由、更稳定的 handoff、更可复用的 machine state，以及更好的验证内耗时表现，同时又不愿意牺牲输出质量。

这次对外发布坚持以下边界：

- 质量优先
- 耗时是当前最主要的优化目标
- token 优化真实存在，但依赖 tier 与任务形态
- 当前版本提供 Codex 的默认启用安装路径
- 其他 agent 宿主可以手动复用，但当前仓库还没有给它们提供打包好的默认安装器

这不是一个“任何任务都会在所有指标上统一变好”的声明。当前版本仍然受限于仓库中已经明确给出的验证任务范围。

在首发之后，我们会继续围绕当前版本加强时间优化和 token 优化，同时守住输出质量不下降这条底线。也欢迎大家把真实工作负载、回归样例、路由不稳定样例和 benchmark 复测结果反馈给我们。
